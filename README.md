# Pocket Arcade · AI Passport Game Firmware

English | [简体中文](README.zh_CN.md)

**Pocket Arcade** (欢乐游戏厅) is the game-firmware that runs on the **FoloToy AI Passport** handheld: an ESP32-C3 based 240×320 pixel handheld console played entirely with three physical buttons. It ships party mini-games for groups and classic single-player games. This repository is the complete firmware source.

> The hardware platform (board, pins, BSP drivers) is inherited from FoloToy AI Passport; this repository focuses on the **game content itself**: party mode, single-player games, the settings page, and the boot animation.

## Features

| Category | Contents |
| --- | --- |
| Party (multiplayer) | Truth or Dare, King's Game, Russian Roulette, Fate Draw, plus a "Bacchus Award" closing animation |
| Single player | Breakout, Snake, Memory Match |
| System | Cyber-terminal boot animation, settings page (brightness / sound, etc.), battery indicator |
| Publishing | Built-in `FAP_SCREENSHOT_V1` screenshot protocol; companion scripts capture, validate, and publish to the FoloToy community |

## Controls

The device has only three buttons, all sharing one ADC resistor ladder on GPIO0:

- **UP / DOWN**: move through menus, steer in games
- **OK (short press)**: enter / confirm
- **OK (long press)**: step back one level (in-game → sub-menu → main menu)

Main menu structure:

```text
Boot animation (cyber terminal)
   └─ "欢乐游戏厅" title page (PLAY · PARTY)
        ├─ Party      → instructions → player count → draw turns
        ├─ Single     → Breakout / Snake / Memory Match
        └─ Settings
```

## Hardware platform

| Capability | Implementation | Notes |
| --- | --- | --- |
| SoC | ESP32-C3 (RISC-V, no PSRAM) | 8 MB Flash |
| Display | ST7789P3, 240 × 320, portrait RGB565, SPI | single DMA buffer, no touch |
| Input | `UP` / `DOWN` / `OK`, GPIO0 ADC ladder | callbacks run in the button task, must not block |
| Audio | ES8311, I2S full-duplex PCM | playback / capture |
| Battery | CW2017 SOC and voltage | optional; degrades safely when absent |
| Flash / log | native USB Serial/JTAG | `COMx` (Windows) / `/dev/ttyACMx` (Linux) |

Pins, I2C addresses, and ADC thresholds live only in `components/bsp/include/bsp_pins.h`; application code must not duplicate these constants.

## Build & flash

Requires **ESP-IDF 5.5.x** (5.5.3 is known good).

```bash
# Activate the ESP-IDF environment (use your install path)
. "$HOME/esp/esp-idf-v5.5.3/export.sh"

idf.py set-target esp32c3     # run once on a fresh checkout or after switching target
idf.py build                  # first build pulls LVGL / esp_lvgl_port / button / esp_codec_dev via Component Manager
idf.py flash monitor          # flash and open the serial monitor
```

> Do not edit files under `managed_components/` (generated by the component manager). If configuration goes stale, use `idf.py fullclean` and reconfigure — never use it to wipe your source changes.

The build artifact is `passport_games.bin` (factory partition), written through USB Serial/JTAG.

## Screenshot protocol (FAP_SCREENSHOT_V1)

The firmware embeds the `FAP_SCREENSHOT_V1` serial screenshot protocol to stream the current screen back to a PC as an RGB565 framebuffer — handy for generating screenshots for community publishing. `tools/capture_games.py` wraps the whole flow.

**Protocol**:

1. The PC sends the command `FAP_SCREENSHOT_V1\n` to the device's serial port;
2. The device replies with a header `FAP_SCREENSHOT_V1 <w> <h> RGB565LE <len>\n`;
3. It then sends `len` bytes of little-endian RGB565 pixels in row-major order (this device is 240×320, so `len = 240*320*2 = 153600`).

**Capture a screenshot** (device must be connected over USB):

```bash
python tools/capture_games.py
# produces capture_screen.png and the adjacent receipt capture_screen.png.fap-capture.json
```

The script waits for the device to boot into the main menu (~20s), then sends the command, receives the full frame, decodes it to PNG, and prints an ASCII preview for a quick sanity check.

## Publish to the FoloToy community

`tools/` also ships publishing helpers (they depend on `publisher.py` from the `folotoy-ai-passport-publisher` skill):

```bash
python tools/do_validate.py     # verify cover / firmware / screen-capture are present and valid
python tools/do_submit.py       # preview the submission (JSON); set confirmed=true in submit_args.json and re-run to actually upload
```

Cover image, bilingual title/description, and other submission fields are configured in `tools/submit_args.json`.

## Project structure

```text
components/bsp/   board drivers (display/button/audio/battery/shared I2C); apps only call bsp_* and ui_pixel_*
main/             boot animation, main menu, game pages, and party logic
tools/            screenshot capture, community validation, and submission scripts
sdkconfig.defaults  ESP32-C3 / USB console / Flash / LVGL defaults
LICENSE            open-source license
```

### Add a new game page

1. Create `main/demo_<name>.c` implementing the `enter` / `exit` / `key` interface;
2. Add the declaration in `main/demo.h`;
3. Add the source file in `main/CMakeLists.txt`;
4. Register it in `s_games[]` / the menu array inside `main/main.c`.
